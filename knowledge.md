# knowledge.md — RoadSense Nigeria

## What this project is

RoadSense Nigeria is a portfolio project that predicts **time-to-failure for Nigerian federal road
segments** using free satellite imagery, open geospatial data and survival analysis, then allocates
maintenance budget with a linear program. It is meant to answer the FERMA 2026 directive for a
geo-referenced national database of failed roads — and go further by predicting which roads fail next.

**Current state (2026-10-29): Phase 2 complete, Phase 3 pilot measured; Gate G0 failed and the
project was re-scoped to corridors.** `src/roadsense/` is a working package with 59 passing tests.
The 850-corridor table, corridor geometry, parquet packaging, DuckDB views and the imagery sampler
all exist and have been run against live data. Modelling, optimisation and serving do **not** exist
yet — do not assume a module or command for those.

**Read `docs/findings.md` before building anything.** It is the register of what was measured, and
several claims in the original spec are known false (see F1–F5, F11).

## Commands

```bash
python -m pip install -e ".[dev]"        # pandas, numpy, pyarrow, duckdb, pytest, ruff
python -m pytest tests -q                # 40 tests, no network needed
python -m ruff check src tests scripts

python scripts/run_gate0.py              # ~65 MB of sources -> segments, events, matches, report
python scripts/build_corridors.py        # -> data/interim/corridors.csv (850 rows)
python scripts/build_geometry.py         # -> data/interim/corridors.geojson (caches paths)
python scripts/publish_dataset.py        # -> dist/dataset/*.parquet + dataset card
python scripts/publish_dataset.py --upload   # needs HF_TOKEN
python scripts/check_warehouse.py        # DuckDB views; prints the headline counts

python scripts/count_tiles.py            # 2,016 imagery tiles containing highway (no download)
python scripts/sample_pilot.py           # one-state imagery pilot, measures real bytes
python scripts/ablate_resolution.py      # 10 m vs 40 m -> docs/resolution-ablation.md
python scripts/backfill.py --shard 1/96 --dry-run    # plan a shard, no downloads
python scripts/backfill.py --shard 1/96 --limit-tiles 3   # smoke test, ~1 min
```

National run: `gh workflow run backfill.yml -f resolution=10 -f shards=96` — **~1–3 h wall clock**
for the 22-month default, ~70 GB streamed and discarded (F21, measured on a runner: 1–4 s per
tile-month, not the 10–30 s the 40 m workstation pilot implied).

The imagery scripts need `.[geo]` (rasterio, pyproj).

Interim caches under `data/` are gitignored. `scripts/run_gate0.py` and `build_geometry.py` are
network-bound; everything else runs offline once the caches exist.

## The nine-layer stack (primary choices from the spec)

1. **Data sources** — GRID3 roads and Open-Meteo are genuinely keyless; **Copernicus CDSE is not** (account + OAuth client required, and the free tier is only 10k Sentinel Hub requests + 10k PU/month, with Batch Processing API unavailable). Use **Digital Earth Africa's Sentinel-2 Rolling Monthly GeoMAD** (10 m, cloud-free, 2019–present, anonymous S3 range reads at `deafrica-services.s3.af-south-1.amazonaws.com`) instead of per-scene Sentinel-2 processing. Others: Digital Earth Africa, GRID3 NGA Roads v1.0 (ArcGIS REST, 6,274,965 segments, fields include `names`, `class`, `road_surface`, `speed_estimate`), Open-Meteo Historical (10k calls/day, **non-commercial only**), NiMet WIS2, HDX, Geofabrik OSM, Overpass, NASA FIRMS, Planetary Computer (data assets need a token — treat as a risk).
2. **Ingestion** — GitHub Actions scheduled workflows on a **public repo** (unlimited standard-runner
   minutes); Lambda container images / Cloudflare Workers / Databricks Lakeflow are alternatives.
3. **Orchestration** — Prefect Cloud free tier primary; Dagster, Kestra, DBOS, Restate, Step Functions are
   alternatives.
4. **Storage** — DuckDB + Parquet on Cloudflare R2 (10 GB, zero egress); MotherDuck, Databricks, BigQuery,
   Supabase, Turso are alternatives.
5. **Transformation** — dbt Cloud Developer (3,000 models/month); dbt Core, SQLMesh, Dataform, notebooks.
6. **Feature engineering** — Hopsworks Community primary, but DuckDB + Parquet is the expected pragmatic
   fallback; Feast, SageMaker Feature Store, Unity Catalog are alternatives.
7. **Survival modelling** — Python: `lifelines` (Cox PH baseline), `scikit-survival` (Coxnet, RSF, GBSA),
   `pycox` (DeepSurv/DeepHit), `p-BART` for uncertainty, `SurvivalEVAL` for metrics. R: `survival`,
   `timereg`, `mets`, `discSurv`, `reda`, `eventglm`. Staged plan: Cox PH → Coxnet → RSF/GBSA → ensemble
   → BART uncertainty → temporal holdout validation.
8. **Optimisation** — 0/1 knapsack over segments; `PuLP` (bundled CBC) or `OR-Tools`; `scipy.optimize`,
   `CVXPY` as alternatives.
9. **Serving/observability** — API: Cloudflare Workers or FastAPI on Vercel or Supabase PostgREST.
   Dashboard: MapLibre GL + React, or Streamlit. Observability: Grafana Cloud. IaC: OpenTofu (preferred over
   Terraform to avoid BSL).

**Hard constraint: $0/month recurring.** Any dependency or service that is not on a permanent free tier is
out of scope. Prefer alternatives that do not require a credit card.

## Conventions and gotchas

- **Label scarcity is the central risk.** **[measured]** The Nigeria OCDS dataset (NOCOPO/BPP) holds
  98,866 processes over May 2021–Oct 2026; only **3,233** are FERMA/FMW road-related, spread as
  2021: 804, **2022: 0**, 2023: 221, 2024: 1,288, 2025: 920, 2026: 0. There is **no coordinate field** —
  matching is by road name + state against GRID3's `names` field. Treat unlabelled segments as
  **censored**, never as negatives — and note censoring is informative (unfunded ≠ undamaged).
- **The 2024 procurement spike is mostly construction.** After `classify_intervention` runs, the
  maintenance series is 2021: 494, 2022: 0, 2023: 230, 2024: 315, 2025: 997 (findings F13). The raw
  2024 bulge is 40% new construction and 34% noise. Year fixed effects stay in but are not
  load-bearing; the real imbalance is that **49% of all maintenance events sit in 2025**, the
  temporal test year.
- **Gate G0 failed: 181 high-confidence matches against a 300 threshold** (findings F11). GRID3
  names only 869 corridors; 113,004 highway segments are unnamed. The measured ceiling is ~200, so
  better matching cannot rescue it. The project models **corridors**, leads with an unsupervised
  satellite index, and uses the 181 interventions as external validation.
- **The modelling unit is a corridor, not a segment.** `corridor_id` is a slug of the GRID3 name;
  it is the join key everywhere. All 850 corridors have geometry.
- **Reframe the model target.** The spec's "time-to-failure" is not supportable: only ~223 project
  titles repeat, so almost no road has two dated interventions. Use a **discrete-time hazard**
  (segment-year rows, label = intervention within 12 months), train 2023–2024 and test 2025. The
  stated "train 2022–2024 / validate 2025–2026" split is impossible because 2022 and 2026 are empty.
- **An intervention is not a failure.** A contract means money was allocated, not that a road broke.
  Exclude new construction and access roads, add year fixed effects, and describe the target as a
  proxy for intervention need in the model card.
- **No free Nigerian AADT exists.** For the optimiser's value term, substitute the van Strien et al.
  2024 global extra-urban AADT series or settlement population in a 5 km catchment, labelled a proxy.
- **Evaluation must be temporal**: train 2023–2024, validate 2025 (2022 and 2026 are empty in the
  source, so the original 2022–2026 split is impossible). Report ROC-AUC, calibration slope, and
  top-decile capture rate — not accuracy.
- **Test the proportional hazards assumption** (Schoenfeld residuals). If it fails, move to time-varying
  covariates or RSF/GBSA rather than reporting the Cox result.
- **Cloud masking is not our problem.** DE Africa's Rolling Monthly GeoMAD is already cloud-free and
  composited.
- **The "20 m overview is 10× cheaper" claim is false** (findings F16). Base tiles are 800 px
  (8 km at 10 m) but overviews are **256 px**, so an 8 km footprint at 20 m needs nine overview
  tiles. Measured per 8 km tile-band: 10 m **934 KB**, 20 m **857 KB**, 40 m **388 KB**, 80 m
  **194 KB**. The sampler defaults to 40 m; `resolution=10` costs 2.4× more.
- **Never read a partial window at the first overview level** — GDAL falls back to streaming the
  whole 172 MB file (measured twice). Always read the full 8 km tile.
- **National imagery scope:** 2,016 distinct 8 km tiles across 97 items (findings F18), 646 KB per
  tile-month at 40 m for 3 bands, 10.7 s each. Backfill ≈ **31 GB / 143 h serial** — must be
  sharded.
- **Centreline NDVI is useless as a road-condition signal** — a 40 m road pixel is asphalt, so
  NDVI ≈ 0 regardless of condition (findings F17). `sampler.rings()` returns an undilated centreline
  plus a 50–150 m verge band; `sampler.contrast()` is `verge − core`.
- **Do not dilate the "road" mask.** An early version grew the centreline by 50 m and called that
  the road; at 40 m that is one pixel, so it sampled the verge it was comparing against and produced
  negative contrast on every corridor. Dilating changes what a mask means (findings F19).
- **The condition signal must run at 10 m, not 40 m.** 40 m preserves level (ρ=0.937) and change
  (ρ=0.917) but flips the contrast sign on 20.6% of corridor-months (findings F19). 10 m costs
  ~70 GB but only ~12–49 h serial (F21) — and it is *faster* per tile-month than 40 m, because one
  base tile replaces nine overview requests.
- **GRID3 has gaps** — accept 5–10% missing segments and document them rather than fabricating coverage.
- **Cost traps**: none currently — public repos get unlimited standard-runner Actions minutes, and
  DE Africa's S3 is anonymous with no requester-pays. Watch instead for free-tier *terms* drift, and
  note that Open-Meteo is licensed for non-commercial use only.
- Scale figures to design against: ~150,000–200,000 segments after filtering to motorway/trunk/primary/
  secondary; ~150 1°×1° weather grid cells; 24-month rolling feature windows.
